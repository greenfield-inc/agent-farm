In three sentences

We add a Markdown export so a user can save one note (SC-1) or every note (SC-2) as plain files. A server serializer turns each note's blocks into Markdown, and one file-name function makes safe, unique names (SC-3). The user gets a "Download as Markdown" item in each note's menu and an "Export all notes" button in Settings.

Before and after

Before

The note menu has Rename, Duplicate, Delete. Settings has Theme and Account. No way to get a note out except copy and paste.

After

The note menu adds "Download as Markdown". Settings adds a "Your data" row with "Export all notes". Screens that must match: n/a because there are no mockups; the new controls reuse the existing menu item and button.

Scope

Constraints

Non-goals

Packages

P-1 · Serializer and export routes

Outcome: the server turns any note into Markdown and serves one note as .md and all notes as .zip. Labels: server, tests · Depends on: nothing

Approach

New module server/export/ with toMarkdown(note) (title as "# ", headings by level, "- [ ]" and "- [x]" for checklists, links as [text](href), fenced code) and fileName(note) (lower-case slug, unsafe characters to "-", note id appended). Two routes in server/routes/export.ts behind the owner check. The zip uses the archive library the server already has. Test first with tdd.

P-2 · Download controls

Outcome: a "Download as Markdown" item in each note's menu and an "Export all notes" button in Settings. Labels: web · Depends on: P-1

Approach

Both controls follow a plain link to the P-1 routes so the browser handles the download. The Settings button shows "Preparing…" and is disabled until the response starts.
