How a Jotter note is stored and shown approved

How things work today, before any export exists. Pure explanation: no plan and no steps.

Gist

A Jotter note has a title and a body. The body is not text: it is a list of blocks, each with a type such as paragraph, heading, checklist item or code. The server keeps that list as JSON. The browser turns each block into what you see. Anything that wants the note as text, such as copy and paste, has to rebuild the text from the blocks, and today only the browser's own copy does that, badly.

How it works now

When you type, the editor keeps a list of blocks in memory. A new line starts a new paragraph block. Typing "# " at the start turns the block into a heading. Pressing the checkbox button turns it into a checklist item with a done flag that starts false. Ticking the box flips the flag; the text does not change.

Two seconds after you stop typing, the editor sends the whole list to the server. The server checks that the body is under 100 KB and stores it in the body column of the notes table, next to the title, the owner and the note id (such as n42).

Links are not separate blocks. They are marks inside a block's text: a span of characters with an href attached. The viewer draws the span as a link. When you copy, the browser copies the visible words and, depending on the target app, may drop the address.

One walkthrough: the "Trip plan" note

You create a note titled "Trip plan", type a heading "Day 1", add a checklist item "Book train" and tick it, then write "See the map" and link the word "map". The stored body is:

[
  { "type": "heading",   "level": 2, "text": "Day 1" },
  { "type": "checklist", "done": true, "text": "Book train" },
  { "type": "paragraph", "text": "See the map",
    "marks": [ { "from": 8, "to": 11, "href": "https://example.com/map" } ] }
]

The title is stored on its own, not as a block. When you open the note again, the viewer reads the list and draws a heading, a ticked box, and a sentence with one link. Nothing in this path produces plain text.

Diagrams

Glossary

Note
One record: id, owner, title, body.
Block
One item in a note's body, with a type and text.
Mark
Formatting on a span of a block's text, such as a link.
Body cap
The 100 KB limit the server enforces on a stored body.

Common misconceptions

  • "The body is Markdown already." It is not. "# " is an editor shortcut; the stored block says "type": "heading".
  • "The title is the first heading." The title is a separate column. A note can have no headings at all.
  • "Titles are unique." They are not. Only the note id is unique.

What this is not
