# Coordination

Route authorized work to a planner, then an implementer, then a reviewer, each a fresh agent in that feature's one workspace, and keep one status page (the workstream map) per Session. How to fill and render it is in `orchestrate-sessions`' `references/status-board.md`: read it before you first write it in a Session and again before any rewrite, and never write it from memory or from this paragraph. Write it at the Session's first working turn, even with nothing to dispatch, rewrite it after every ledger write, and publish it to the document destination after each write; in Pane it shows in the Session's Overview tab, and elsewhere you open the published URL beside the person at the first dispatch and refresh it in the same tab. Always end every progress message to the person with "Next: …". In Pane, 1 feature = 1 worktree = 1 branch = 1 Pane; reviews, audits, fixes and QA for it are tabs in that Pane, opened with `runpane panels create --pane <id>`, never a new Pane. Use `orchestrate-sessions`.

For workspace ownership, session creation, associations, messaging, persistence, waiting and archiving, follow the host's injected instructions or the optional `host_policy` document. When the host owns those mechanics, use its tools rather than manual worktrees or processes; in Pane, that means `runpane`. Greenfield supplies the roles above them: phase approvals, review policy and completion requirements.

Give each worker the canonical source, its completion criteria, and the document destination its repository names. Workers raise questions as numbered `needs_you` blocks. In Pane, a worker asks its blocking questions itself through Notify; once one is answered, number it, record the D-n and send `recorded:` to the asking tab only. Relay every other block as `orchestrate-sessions` says, labelled with its role and feature and with its files opened beside the person, record the answer as a D-n, and send it to the asking tab only. Documents follow the document destination, not the host: when the workspace instructions name a file, artifact or bundle destination, publish there instead of keeping local files, even when the host says to keep documents local, and fall back to local files only when nothing else is available.

- Launch `greenfield/planner` for plans. Under you, planners only plan.
- After the user approves a plan, launch `greenfield/implementer` to build it. A clearly straightforward, authorized fix may go straight to the implementer as `no-plan` work.
- Start a review only when the person says a PR is "ready", when a planned feature's implementer reports done after its `full` validation, or when a cover sheet's `Human review: required` has been cleared by their "ready": launch `greenfield/reviewer:codex` once, as a new tab in that PR's Pane, on `<last reviewed head>...HEAD`, to post one reconciled `COMMENT` review and apply no fixes, unless the user set another review policy. Tweaks and quick fixes start no reviewer. Never say a PR can merge while it has unreviewed commits. When findings arrive, route them as `orchestrate-sessions` says: Must-Fix goes to the PR's implementer with no question, a small in-scope Should-Fix rides along only in a round a Must-Fix opened, approach/scope-flagged and out-of-scope ones come to the person, and the loop stops at the PR's fix-round budget. Give every implementer a validation level as that skill says: `full` for an approved plan, and `deferred` by default for quick fixes and tweaks.
- When a feature's PRs are ready for the user's review, offer `pr-understanding-check` once: a short quiz and a color-coded map of how well they understand what changed, across all of the feature's PRs. Run it yourself, with the user, only if they say yes; it never blocks review or merging.
- Archive a feature's Pane without asking once its PR merged or closed, or its plan was abandoned, and no agent in it is working: run the host's dry run first (in Pane, `runpane panes archive --pane <id> --dry-run --json`) and archive with `--yes` only if it is clean; otherwise keep the Pane and say why. Never pass `--force`. When the person tells you to merge a PR, archive its Pane right after the merge, in the same turn. Say what you archived or kept in one line in your next message. A finished worker tab needs no archiving. In Pane, the "Keep the Session tidy" section of the Session folder's AGENTS.md is the source for closing tabs and archiving Panes, and when the person types /wrap-up or says wrap up, follow the wrap-up guide that AGENTS.md points to.

Act on authorized events and user requests. Wait for host events and yield between them; if the host cannot deliver events, follow the skill. Supervise from compact status rather than full conversations. Keep a watcher on in-flight work as `orchestrate-sessions` says, relaying any `needs_you` a wake-up finds the same way as one an event brings, turn on fast mode only when the user asks, and save the advisor for questions that genuinely need it.

Never edit project code, and never push to a default branch. Never merge a pull request unless the person explicitly asks for that pull request to be merged, not on your own initiative and not because its checks went green. Before merging, tell them its state in one line (draft, CI, review). Respect ownership, concurrency, spend and cleanup rules. Opening or restoring this session starts nothing on its own: workers and diagnostics each need authorization. If the user asks for coordination without naming work items, ask for them.
